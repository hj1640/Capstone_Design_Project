# 8단계 — 전체 흐름 검증과 팀 인수

D-002/D-007/D-009/D-010/D-016/D-049, 2026-11-02. 기존 0~7단계를 연결한 PC 합성 통합 검사와 인수 자료를 추가했다. 이는 실제 사용자 앱 출시 완료 판정이 아니다.

## 이번에 수정한 통합 경계

- 실제 ML Kit 결과는 온라인 주문 파서로 처리한다. 명시된 주문일만 날짜 후보로 추출하며 배송일이나 오늘로 대신 채우지 않는다. 누락/잘못된 날짜/서로 다른 주문일은 사용자 확인 대상이다.
- 주문 결과 확인 화면과 수기 입력에서 실제 구매일을 확인해야 등록된다. 식품 후보도 사용자가 선택한다. 예전 Jaccard 임계값을 자동 확정 기준으로 승계하지 않았다.
- 실제 OCR이 실패하거나 native 모듈이 없으면 오류를 알린다. 합성 예제는 별도 개발용 동작으로 연다. 기존 종이 영수증 mock 파일은 과거 자료이며 실제 OCR 경로의 fallback으로 쓰지 않는다.
- 주문 품목 등록은 공통 buildRegistration 함수로 검증한다. 미확인 보관 조건은 ‘미정’, 소비기한은 null, 미확인 영양정보는 없다고 표시한다. 기존 7일/모의 DB 일수를 새 등록 기본값으로 쓰지 않는다.
- 등록한 품목과 구매 이력도 개인 SQLite envelope에 보존한다. 품목 삭제/소진 뒤에도 구매 이력은 남는다. 새 production 세션에 개발용 seed 이력을 주입하지 않는다.
- 개인 날짜를 여러 번 수정한 뒤 해제해도 원래 기한 미정(null)으로 돌아가도록 고쳤다. 등록과 날짜 편집은 영속 저장 성공 뒤 화면에 반영된다.
- 오늘은 기기 현지 달력 날짜, 일수 더하기는 UTC calendar 연산을 사용한다. 서울/미국 시간대 및 일광절약 경계에서 날짜 이동을 검사했다.
- 원본 구매 추천에는 전체 이력 재계산과 미승인 숫자들이 남아 있다. config/purchase-forecast.json을 disabled/null로 두어 운영 추천으로 사용하지 않는다. 증분 예측 adapter와 평균/EWMA 선택은 별도 미완료 조건이다. 아래 구매일 평가는 오프라인 실험이다.

## 실제 실행한 전체 흐름

합성 온라인 주문 텍스트 → 공통 파서(주문일/수량) → 상품 검색/식품 연결 → 사용자 선택 → 실제 구매일로 등록 → 기한 미정 표시 → 개인 날짜 편집/재시작 복원 → 동의/HTTP 제출 → 임시 합성 서버의 운영자 검토 → N 조건을 만족한 테스트 규칙 조회 → 철회 → 규칙 제거/개인 날짜 유지.

server/check_full_flow.py의 검토 callback과 N=1은 테스트 전용이다. production API에 그 callback을 추가하지 않았고 config/feedback-policy.json은 계속 비활성이다. 실제 이미지 OCR, Android SQLite/UI 동작, 실제 데이터/정책 승인을 이 검사로 대신하지 않는다.

## 검증 재현

Node 24.22.1 / Python 3.12.14 기준. 새 clone에서는 pnpm 설치와 5단계 모델 준비 절차를 먼저 완료한다.

```powershell
pnpm install --frozen-lockfile
# 모델 준비: docs/STAGE_5_MODEL_AND_APP.md 순서 실행
python scripts/verify_stage8.py
```

이 명령은 서버 단위 검사, 2/3/4/5단계 회귀, 6/7단계 HTTP, 전체 흐름, 다음 구매일 분석, 시간대 경계, 타입/lint, Android Metro export의 13개 검증 그룹을 실행한다. 실패가 있으면 종료 코드 1과 보고서를 남긴다. 실행에는 loopback 서버와 임시 파일 권한이 필요하다.

결과: benchmarks/STAGE8_RESULTS.md, 원시 기록/환경/소스 해시: benchmarks/stage8-verification.json. 전체 흐름: stage8-flow-report.json. Android bundle은 APK 빌드가 아니다. Native 모듈의 실제 실행을 입증하지 않는다.

## 다음 구매일 분석 예제

scripts/stage8-purchase-eval.mjs는 2개의 합성 사용자 구매 이력에서 미래 이력을 보지 않는 walk-forward 비교를 수행한다. 증분 산술평균과 직전 간격을 별도 실험으로 비교하며 운영 모델을 선택하지 않는다.

예측 표본 5개에서 평균 간격 모델 MAE는 약 3.033일, 직전 간격 모델은 4.2일이었다. 이전 구매 수량 1/2별 다음 간격도 기록하지만, 패턴을 넣어 만든 합성 자료이므로 실제 사용자 행동/수량의 인과 효과를 입증하지 않는다. 평가 대상은 실제로 뒤에 관찰되는 **다음 구매일**이며 실제 소비량이나 소진일이 아니다. 반올림 전 기대 간격으로 오차를 계산했고 제품 표시 날짜/최소 이력/lead_days는 미정이다.

파일: benchmarks/stage8-purchase-report.json. 발표 시 합성값이라는 표기를 붙인다. 실제 사용자 시계열이 없으므로 실제 성능 숫자로 발표하지 않는다.

## 팀 인수 자료
