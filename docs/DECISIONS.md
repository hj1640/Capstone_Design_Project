# 팀 작업 결정 및 미정 값

출처: 사용자가 이 작업 세션에 제공한 프로젝트 지침과 2026-10-30까지의 직접 요청. 기존 인수인계 D-ID를 유지한다. 전체 과거 대화가 저장소에 포함되어 있다는 뜻은 아니다.

| ID | 상태 | 내용 |
|---|---|---|
| D-001 | 확정 | SW 구현. 냉장고 센서·카메라 하드웨어는 SW 필수 범위 밖. |
| D-002 | 확정 | 온라인 주문내역·온라인 영수증 입력. 종이 영수증은 현재 핵심 범위 밖. |
| D-003 | 확정 | 약 1,200 후보 → 약 600 선별 계획. 600개 고유 클래스가 아님. 실제 목록 미확보. |
| D-004/D-005 | 확정 | 우유·치즈·요거트 등 직관적 식품명. 보관 조건 차이만으로 화면 식품명을 과도하게 분할하지 않음. |
| D-007 | 확정 | 추정 잔여량은 내부 예측 상태. 사용자에게 추정 잔여량 수치·바를 표시하지 않음. 현재 앱에는 이전 사양이 남아 있어 후속 수정 필요. |
| D-008/D-010 | 확정 | 구매 기록은 실제 소비 측정이 아님. 예측 평가는 실제 다음 구매일을 기준으로 하고 변수 효과·모델 비교를 포함. |
| D-009/D-023/D-024 | 미정 포함 | 구매주기 통계는 증분 처리. 산술평균/EWMA 선택, alpha·d·가중치·최소 이력·임계값은 미정. |
| D-011 | 기준선·충돌 확인 | 인수인계에는 Kotlin 기준선이 있었으나 현재 실제 저장소와 Notion은 React Native + Expo. 사용자가 이 저장소에서 계속할 것을 요청했으므로 이번 작업 대상은 기존 Expo 앱. Kotlin 이식 작업으로 바꾸지 않음. |
| D-013/D-015 | 기준선 | 다국어 MiniLM, FP32/ONNX/INT8 비교 계획. Notion의 ko-sroberta 실험과 최종 선택은 구분. 모델·토크나이저·출력 차원·모바일 지원을 실물 파일로 확인. |
| D-025/D-029/D-030 | 자료 미확보 | 실제 선별 목록·FoodKeeper 원본 XLSX·최종 버전 미확보. 기존 16개 예시나 Notion의 40개 DB와 혼동하지 않음. |
| D-039 | 사용자 요구 | 전체 상품명 보존 상품 DB(2층)와 표준 식품 DB(1층)를 연결해 잘린 주문 상품명을 분류하고 참고 기한 반환. |
| D-040 | 사용자 요구 | 사용자 기한 수정 수집 → 신뢰도 검증 → 서버 식품별 통계·공유 기본값 갱신. |
| D-041 | 확정 | 0단계부터 단계별 진행. 기존 GitHub·Notion·Expo 연결을 유지하고 조원이 GitHub에서 이어갈 수 있게 공유. 0단계 이후 기능은 아직 구현 완료가 아님. |
| P-001 | 제안 | 상품 등록 시 표준 식품 연결을 확인·저장하고 조회 시 재사용. 미연결 상품만 분류 후보 제안. |
| P-002 | 제안 | 개인 기한 수정은 개인 기록에 적용, 공유 기본값은 검증 후 버전 단위 반영. |

## 아직 운영값을 정하지 않은 항목

- 상품 검색 방식, 후보 수, 유사도·후보 간 점수 차이 기준, 상품 DB 범위·권한·출처.
- 수정값의 의미(포장지 표시 날짜 / 구매 후 남은 기간 / 개봉 후 기간 / 사용자 추정).
- 조건별 통계 구분, 사용자 식별·동의, 최소 서로 다른 사용자 수 N, 이상값 기준·가중치.
- 공유 통계의 산술평균/가중평균 선택, 수정·취소 기여분 처리, 공개 반영·되돌리기 정책.
- 서버 기술·배포·인증·동기화 방식. 제품 연결 확인과 통계 신뢰도는 별도 검증.

기존 코드의 0.5/0.15/0.12 매칭 기준, DB 미일치 시 7일, 예시 보관일수는 **현재 구현 관찰값**이며 사용자 승인된 운영 정책이 아니다. 새 정책으로 조용히 승격하지 않는다.
