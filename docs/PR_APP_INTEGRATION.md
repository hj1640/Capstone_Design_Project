# PR 제목

feat: 포장지 소비기한 개인 평균과 앱·서버 재전송 및 배포 경로 연결

## 문제와 결과

기존 앱의 날짜 수정이 검증된 개인 통계·지속적 서버 연결로 이어지지 않았고, 과거 공용 평균 실험과 최신 개인별 요구가 섞여 있었습니다. 지류/쿠팡의 사용자 확인 구매에 대해 포장지 날짜−구매일을 개인·식품명·보관 조건별로 계산하도록 정리했습니다. 같은 구매 수정·재전송은 건수를 늘리지 않고, 철회는 기존 기여를 제거합니다.

개인 코드 등록 및 SecureStore 연결 보관, 앱 전경 복귀/오프라인 재시도, 요청 멱등성/revision 충돌, 별도 Waitress 서비스 및 DB 백업, HTTPS/Docker 배포 설정과 기존 Expo preview APK 경로를 추가했습니다. 원격 main에 없던 로컬 0~8단계 및 D-050/D-051을 포함하는 인수 PR입니다.

## 설계와 검증

- 최신 사용자 결정 D-050: 지류+쿠팡, 포장지 날짜, 개인 평균. 공용 N명/임의 이상값 가중치를 적용하지 않습니다.
- 순서 독립 산술평균, 입력 의미·달력·소유권·중복 검사. 평균은 식품 안전기간을 증명하거나 포장지 날짜를 대체하지 않습니다.
- PC 결과: `benchmarks/DEPLOYMENT_RESULTS.md` 및 `deployment-verification.json`의 실행 로그/소스 해시 참조. 실제 Waitress HTTP, 프로세스 재시작, 응답 유실, 동시 수정, 철회, 인증 격리, 백업, 타입/lint/JS 번들을 검증합니다.
- 상세 추적: `docs/APP_INTEGRATION_REPORT.md`. 배포 방법: `docs/APP_DEPLOYMENT.md`.

## 적용 조건과 남은 검증

별도 서버·도메인이 아직 없습니다. 기존 Expo projectId/package/서명 확인, 실제 HTTPS 서버 배포, 새 APK 빌드·설치, 휴대폰 인수가 필요합니다. JS 번들 성공은 APK 성공이 아닙니다. 실제 1,200/600 상품 목록, 실제 OCR 정확도와 휴대폰 모델 성능은 검증하지 않았습니다. 구형 데이터는 자동으로 포장지 관측/다른 계정으로 이동시키지 않습니다.

기본 브랜치 병합 및 서비스 출시 승인을 자동으로 요청하는 PR은 아닙니다. 팀이 코드와 인수 조건을 검토할 수 있도록 준비한 변경입니다.
