## 실제 데이터 연결

약 1,200 후보 → 약 600 선별은 기획 규모이며 고유 클래스 600개가 아니다. 실제 목록/최종 FoodKeeper XLSX의 파일과 버전은 아직 확보·검증하지 않았다. 합성값이나 이전 indexed text를 실제 기간 근거로 바꾸지 않는다.

실제 카탈로그·조건 선택·참고 규칙 조회를 앱 등록에 연결하는 최종 작업이 남아 있다. 현재 앱의 새 등록은 기본 기한을 미정으로 두고 사용자의 날짜 입력을 우선한다. 개발용 합성 상품 매핑을 실제 구매품의 확정 식품 ID로 저장하지 않는다.

## 구매 예측

운영용 증분 산술평균/EWMA, 단위/수량 처리, 최소 이력, lead_days, 관측 모델이 미정이다. 예전 전체 이력 추천 휴리스틱은 비활성화했다. 실제 반복 구매 시계열에서 사용자별 패턴과 수량/간격 효과, 다음 구매일 MAE 및 모델 비교를 검증해야 한다. 구매 기록을 실제 소비 측정으로 부르지 않는다.

## 앱/서버 연결

기존 EAS owner/projectId/Android package와 build source SHA를 팀 계정에서 확인해야 한다. SQLite/Crypto/ONNX가 포함된 새 개발 APK로 시험하고 기종/OS/커밋을 기록한다. PC export 결과를 실기기 통과로 바꾸지 않는다.

로컬 개발 토큰 API를 운영 로그인/공개 서버로 그대로 사용하지 않는다. 실제 계정/동의/보관·삭제/호스팅을 정하고 적용 범위를 검토한다. 신뢰도 설정은 config/feedback-policy.json에서 disabled/null 상태이며, 승인 근거 문자열만 넣는 것이 실제 승인을 인증하는 기능은 아니다.
