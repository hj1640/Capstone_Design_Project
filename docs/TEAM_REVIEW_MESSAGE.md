# 팀 공유 설명

이번에 0~8단계 코드를 실제로 다시 검토하고, 최신 요구에 맞게 개인 평균 경로를 정리했습니다.

- 입력은 지류 영수증과 쿠팡 주문내역입니다. 인식 결과의 식품명·구매일·수량을 확인하고 수정할 수 있습니다.
- 수정값은 포장지의 소비기한입니다. 평균내는 값은 ‘포장지 날짜에서 구매일을 뺀 일수’이고, 실제 섭취일이나 개봉 후 보관일수가 아닙니다.
- 다른 사람과 합치는 공용 평균이 아니라, 본인의 같은 식품명·보관 조건에 해당하는 구매 기록 평균입니다. 한 구매의 날짜를 고치면 기존 값을 바꾸고, 반영 철회하면 그 기여를 뺍니다.
- 기존의 50% 허용 편차/가중치/N명 규칙은 실험용이었고, 같은 입력이라도 순서에 따라 결과가 달라지는 반례가 나왔습니다. 개인 평균에는 이 규칙을 쓰지 않습니다.
- 현재 필터는 달력 형식, 날짜의 의미, 보관 조건, 개봉 상태, 중복/동시 요청을 확인합니다. 멀리 떨어진 숫자라는 이유만으로 정상 포장지 값을 버리지 않습니다. 대신 오타/거짓 라벨까지 자동 판별한다고 주장하지 않습니다.
- 평균과 반영 건수를 표시하며, 이 평균으로 포장지 날짜를 자동 덮어쓰지 않습니다.

PC에서는 실제 HTTP 서버에 연결해 등록→수정→집계→재시도→철회와 계정 분리 등을 검사했습니다. 실행 로그와 반례는 `benchmarks/REVIEW_RESULTS.md`, 이유와 코드 연결은 `docs/REVIEW_FINAL.md`에서 볼 수 있습니다.

현재는 팀 시험 후보입니다. 실제 Android 사진 인식/화면/SQLite 재시작, 기존 Expo 빌드와의 호환성, 실제 상품 DB, 운영 인증·HTTPS 서버는 추가 확인이 필요합니다. GitHub에 올렸다고 기존 설치 앱에 자동 적용되지는 않습니다. 팀 빌드 설정을 확인한 뒤 새 개발 APK에서 `docs/TEAM_SETUP.md`의 시나리오를 같이 확인하면 됩니다.
